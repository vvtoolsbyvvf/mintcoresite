MINTCORE — GITHUB + RAILWAY

This deployment runs the dashboard and PHP relay together on Railway. GitHub
stores the source code; Railway builds and hosts it. GitHub Pages is not used.

1. Push the project to a GitHub repository. Keep it private if you plan to put
   credentials in bridge-config.php. Anyone with access to that repository can
   read those values.
2. In Railway, create a project from that GitHub repository and deploy it.
   The repository-root Dockerfile starts the PHP web server on Railway's PORT.
3. Add a Railway volume mounted at /data.
4. To avoid Railway variables, edit the existing website/bridge-config.php
   before pushing and replace the two placeholder values. Keep the GitHub
   repository private; anyone with repository access can read those values.
   The volume at /data is detected automatically. Alternatively, you can set
   the secrets as Railway service variables to keep them out of GitHub.
5. Generate a public HTTPS domain for the Railway service. Open the domain to
   see the MintCore dashboard, and sign in with MINTCORE_DASHBOARD_PASSWORD.
6. In GemHost, edit plugins/MintCore/config.yml. Keep web-console.enabled true
   and set:

   relay:
     enabled: true
     url: "https://YOUR-RAILWAY-DOMAIN/bridge.php"
     secret: "THE SAME VALUE AS MINTCORE_BRIDGE_SECRET"

   Replace the example domain and secret. Save the file, then fully stop and
   start the Purpur server from the GemHost panel.

The Railway domain serves both the HTML dashboard and bridge.php, so browser
requests stay on the same origin. The router blocks direct requests to PHP
configuration files and relay storage. Keep the Railway variables private.
